## Root cause (confirmed 2026-08-07T15:07:24+09:00)

- Mechanism: `healthcheck.sh` regards an owned PID as healthy without a liveness signal, so a router stuck inside long polling remains healthy forever. Since `start_router` also launches a replacement without first stopping a still-running unhealthy PID, the router's singleton poll lock would reject that replacement.
- Evidence: `healthcheck.sh:74-83` has only PID/cwd/cmdline checks; `telegram_codex_bot.py:457-482` obtains a singleton poll lock before writing `router.pid`; `test_healthcheck.sh` reproduces a live stalled router remaining unchanged.
- Toggle proof: with a fresh heartbeat requirement, the stalled fixture must be terminated and replaced; without it, the same fixture remains the recorded healthy PID.
- Fix scope: `healthcheck.sh`, `telegram_codex_bot.py`, `test_healthcheck.sh`, and `test_telegram_codex_reliability.py`.
